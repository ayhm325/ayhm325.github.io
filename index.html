ENGINEERING DECISIONS

Designing for consistent outcomes.

Examples of engineering concerns addressed in the DVLD source.

Multi-step business operations

Problem A licensing workflow can change several related records.

Approach Services coordinate work through a shared DbContext and Unit of Work transaction.

Why it matters Related changes can commit or roll back together, protecting data consistency.

Concurrent requests

Problem Two requests may compete for the same appointment or licensing state.

Approach Sensitive workflows use Serializable transactions, SQL application and row locks, and database constraints.

Why it matters The database helps enforce business invariants under concurrent access.

Securing API access

Problem Clients must not be trusted to enforce staff permissions.

Approach JWT bearer authentication and server-side role policies protect API endpoints.

Why it matters Authorization is applied at the backend boundary.

Reliable testing

Problem Persistence tests need isolation from real application data.

Approach Separate unit and integration suites use isolated SQL Server test databases and safety checks.

Why it matters Tests can exercise database behavior without targeting the production database.
